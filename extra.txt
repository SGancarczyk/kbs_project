WHAT CHANGED — KBS TRAVEL CHATBOT
===================================
Three files were modified: knowledge_base.py, chatbot.py, inference.py.
All changes stay within the course scope (NLP pipeline, rule-based systems,
fuzzy logic, certainty factors, forward chaining).


1. BIGGER VOCABULARY (knowledge_base.py)
-----------------------------------------
The synonym dictionaries that map user words to dataset values were expanded:

- Continents: city names now work as region shortcuts (e.g. "Tokyo" -> Asia,
  "Bali" -> Asia, "Paris" -> Europe, "Cape Town" -> Africa, "NYC" -> North
  America). Region phrases like "Southeast Asia" or "Latin America" also work.

- Budget: added words like "backpacking", "thrifty", "splurge", "five stars",
  "first-class", "comfortable", "balanced".

- Climate: added "humid", "sweltering", "crisp", "brisk", "beach weather".

- Duration: added "mini trip", "few days", "two weeks", "sabbatical", "gap year".

- Lifestyle: roughly doubled. New words include "kayaking", "scuba diving",
  "skiing", "hot springs", "street food", "cathedral", "bazaar", "coral reef",
  "vegan", "rooftop", "zip line", and many more per category.


2. NEW SEASON/MONTH SLOT (knowledge_base.py + chatbot.py + inference.py)
--------------------------------------------------------------------------
The bot now asks when the user is travelling, and uses it for smarter
climate matching.

How it works:
- A new SEASON_SYNONYMS vocabulary maps season names (winter/spring/summer/
  autumn), all 12 month names, and informal terms (xmas -> December,
  easter -> March) to month numbers.
- The chatbot extracts these via the same NLP pipeline used for all other
  slots and stores them in query["travel_months"].
- The inference engine then looks up the city's actual temperature for those
  specific months from the CSV (instead of the yearly average). So "warm in
  December" correctly favours Sydney over Stockholm.
- Multiple months work too: "June or July", "winter and May" all get combined
  and averaged across the relevant months.


3. MORE NATURAL DIALOGUE (chatbot.py)
--------------------------------------
The conversation was made to feel more human:

- Questions rewritten to invite a full sentence instead of a keyword list.
  e.g. "What kind of budget are you working with?" instead of
  "(cheap, mid-range, or luxury)".

- Acknowledgement openers replaced with calmer, less repetitive ones:
  "Got it.", "That helps.", "Makes sense." instead of "Perfect!", "Awesome —".

- Small-talk recognition added: greetings, "how are you", "thanks", laughter
  etc. get a short friendly reply before the conversation continues.

- "Not really", "not really sure" and similar phrases now correctly register
  as skipping a question instead of triggering a confused response.

- Four rotating "I didn't understand" messages instead of one fixed one,
  all written to encourage a fuller answer rather than keyword input.

- Recommendation header changed to "Here are a few destinations that fit
  what you're looking for:" (less robotic).

- No-results message now says "I couldn't find any destinations that match
  all of those preferences at once. If you're open to being a little more
  flexible..." (more helpful).

- Exit message: "Thanks for stopping by. Have a great trip..."

All original code comments were kept. New comments were added for every
new feature explaining what it does and why.


ONE THING TO KNOW ABOUT BUDGET LOGIC
--------------------------------------
If someone says "not too expensive, not too cheap", the NLP excludes both
Luxury and Budget — it does NOT directly infer Mid-range. Mid-range cities
end up on top because the other two are penalised. This is a side effect of
the existing certainty factor scoring, not genuine reasoning. A proper
forward-chaining rule (IF exclude:Luxury AND exclude:Budget THEN include:Mid-range)
could be added to rules.py to make it explicit — worth mentioning to the
professor as an example of how forward chaining adds intelligence on top of NLP.
