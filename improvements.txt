CHATBOT PROJECT — CHANGES FROM OLD VERSION TO NEW VERSION
==========================================================
(Old = chatbot__3_.py / nlp.py (no NLTK) / knowledge_base.py (no countries/seasons))
(New = chatbot.py / nlp.py (NLTK) / knowledge_base.py (with countries/seasons/lifestyle TF-IDF))


================================================================
CHATBOT.PY
================================================================

1. TWO NEW SLOTS ADDED
   Old slots (5): continent, duration, budget, climate, lifestyle
   New slots (8): continent, COUNTRY (new), SEASON (new), duration, budget, climate,
                  LIFESTYLE_WHAT (new), LIFESTYLE_HOW_MUCH (new)

   - "country" slot: user can now say a specific country like "Japan" or "Brazil".
     The bot pins results to that country AND auto-fills the continent slot so it
     never asks a redundant region question afterwards.
   - "season" slot: user can now say a month ("July") or season ("summer").
     The bot stores the month numbers and the inference engine uses monthly
     temperature data instead of a yearly average when scoring climate.
   - "lifestyle_what" slot (replaces old single "lifestyle" slot):
     The bot shows all 9 lifestyle dimensions explicitly and asks the user to
     describe which ones appeal to them in free text. TF-IDF cosine similarity
     (same approach as chatbot__4_.ipynb) detects which dimensions match.
   - "lifestyle_how_much" slot:
     After detecting dimensions, the bot asks how important each one is (1–5).
     The user can answer naturally ("cuisine is a must, nightlife maybe a 3")
     and the bot parses per-dimension ratings from the free-text answer.

2. LIFESTYLE SCORING NOW USES TF-IDF COSINE SIMILARITY
   Old: keyword scanning via LIFESTYLE_SYNONYMS dictionary — a word had to exactly
        match a vocabulary entry. Every matched dimension got hardcoded weight 5.
   New: TF-IDF vectorizer (sklearn) matches free-text sentences against
        LIFESTYLE_DESCRIPTIONS (keyword-rich strings per dimension). This means
        "I enjoy walking through old towns and trying local street food" correctly
        maps to culture + cuisine without requiring exact keyword matches.
        Per-dimension weights 1–5 replace the flat weight-5 default.
   Libraries used: sklearn.feature_extraction.text.TfidfVectorizer (same library
   as chatbot__4_.ipynb notebook).

3. NEW MODULE-LEVEL FUNCTIONS FOR LIFESTYLE
   - _match_lifestyle_dims(text): TF-IDF cosine similarity matching against
     LIFESTYLE_DESCRIPTIONS, returns {dim: score} for dims above threshold.
   - _score_segment(segment): scores a text clause as 1–5 using digit detection
     first, then longest-phrase-first intensity word matching.
   - _extract_per_dim_ratings(text, dims): splits answer into clauses by
     punctuation/conjunctions, scores each clause, assigns per-dimension weights.
     Handles "all of them are a 4", "the rest I don't care about", global fallback.
   - _INTENSITY_WORDS / _INTENSITY_SORTED: intensity vocabulary sorted
     longest-phrase-first so "don't really care" beats "really" in the same clause.
   - _ALL_PHRASES / _REST_PHRASES: phrase sets for "all of them" and "the rest"
     to support global and remainder scoring in one natural answer.

4. NEW HELPER METHODS IN TravelChatbot
   - _lifestyle_pending_dims(): finds dimensions stored as float placeholders
     (detected in lifestyle_what but not yet rated by the user).
   - _lifestyle_how_much_question(): builds a dynamic natural-language question
     listing only the pending dimensions, inviting a 1–5 or descriptive answer.
   - _slot_index(name): returns the index of a named slot in _slots().
   - _sanitize_lifestyle_weights(): before inference runs, replaces any remaining
     float placeholders with default weight 3 (moderate) so inference always
     receives clean integers.

5. LIFESTYLE EXTRACTION SCOPED TO LIFESTYLE SLOTS ONLY
   Old: lifestyle keywords were scanned on every message throughout the conversation.
   New: TF-IDF detection and exclusion extraction only run when pending_slot is
        "lifestyle_what" or "lifestyle_how_much". Messages answering continent,
        budget, season etc. never accidentally fill lifestyle preferences.

6. EXCLUSION-BEFORE-INCLUDE IN LIFESTYLE_WHAT
   nlp.extract() runs for exclusions BEFORE TF-IDF adds includes. This means
   "not too much nightlife" correctly excludes nightlife rather than including it
   (TF-IDF would score the word "nightlife" positively regardless of negation).

7. FLOAT PLACEHOLDER PATTERN FOR TWO-PHASE LIFESTYLE
   Phase 1 stores raw TF-IDF cosine scores as floats (e.g. 0.37) in
   self.query["lifestyle"]. These signal "detected but not yet rated".
   Phase 2 replaces them with integers 1–5 from the user's rating answer.
   _lifestyle_pending_dims() identifies floats; _sanitize_lifestyle_weights()
   cleans up any remaining floats before inference.

8. GO INTENT: SHORT MESSAGE GUARD
   Old: any message containing "show me" triggered the recommend intent, including
        long preference sentences like "I want to go somewhere like France, show
        me your picks" — skipping preference extraction entirely.
   New: recommend intent only fires for messages of 8 words or fewer, OR exact
        command phrases like "go", "done", "show results". Long messages are
        processed for preferences first, then results are shown if all slots done.

9. GO INTENT: LIFESTYLE GATE
   Old: "go" jumped straight to results even if lifestyle had never been asked.
   New: if the user types "go" before any lifestyle input has been given, the bot
        asks the lifestyle_what question first with a brief explanation. This ensures
        the cosine similarity always has dimensions to score on.

10. _SKIPPED TRACKING: NOW CORRECTLY SET
    Old: self._skipped was initialised in reset() but never written to when a skip
         happened, so the country slot never auto-skipped after continent was skipped.
    New: self._skipped[self.pending_slot] = True is set before resolving the slot,
         so _slot_filled("country") correctly reads _skipped["continent"].

11. SLOT QUESTIONS REWRITTEN — MORE CONVERSATIONAL
    Old: "Where would you like to go? (e.g. Europe, Asia, South America - or say 'anywhere')"
    New: "Do you already have a region in mind? You can mention somewhere specific like
         Europe or Southeast Asia, or just say you're open to anything."
    All 5 original questions were rewritten in this style. The new lifestyle_what
    question explicitly lists all 9 dimensions so users know what to respond to.

12. SKIP_WORDS AND SKIP_PHRASES EXPANDED
    Old SKIP_WORDS: 9 words
    New SKIP_WORDS: ~30 words, adding filler words so "i don't mind", "open to
                    anything" etc. are correctly identified as skips.
    Old SKIP_PHRASES: 10 phrases
    New SKIP_PHRASES: ~20 phrases adding "whatever works", "no idea", "surprise me",
                    "up to you", "not bothered", "not fussed" etc.

13. SKIP DETECTION USES NLTK TOKENIZER
    Old: tokens = t.split()
    New: tokens = [tok for tok in nlp.tokenize(t) if tok.isalpha()]
    Effect: "don't" now splits to ["do", "n't"] so contractions work correctly.

14. SMALL-TALK HANDLING ADDED (entirely new)
    Full _SMALL_TALK dictionary with varied replies for greetings, how-are-you,
    thanks, cool/nice/ok (ambiguous — may fall through), lol/haha, not-sure/idk.

15. "I DIDN'T UNDERSTAND" REPLIES NOW ROTATE
    Old: one fixed confused reply.
    New: _CONFUSED_REPLIES list with 4 different messages; random.choice().

16. ROTATING OPENERS ARE CALMER/MORE NEUTRAL
    Old: ["Perfect!", "Got it!", "Noted —", "Great choice —", "Awesome —", ...]
    New: ["Got it.", "That helps.", "Sounds good.", "Thanks for sharing.", ...]

17. NEW INTENT: "more_like"
    If the user says "more like Tokyo" or "similar to Paris", the bot copies that
    city's budget/climate/lifestyle as the user's preferences and recommends.

18. QUERY DICT EXTENDED
    Old keys: regions_include, regions_exclude, climate, climate_exclude, budget,
              budget_exclude, duration, duration_exclude, lifestyle, lifestyle_exclude
    New keys: + countries_include, countries_exclude, travel_months

19. _blocking_vocabulary_for() UPDATED
    Now blocks from 7 maps — added COUNTRY_SYNONYMS and SEASON_SYNONYMS.

20. _has_meaningful_preferences() UPDATED
    Now checks 13 query keys including countries_include, countries_exclude,
    travel_months (travel_months alone is meaningful).

21. WORDING CHANGES IN RESPONSES
    Exit, restart, reject, skip-ack, skip-all, confused replies all updated
    to be more conversational. See original document for old/new pairs.

22. import random ADDED


================================================================
NLP.PY
================================================================

1. TOKENIZATION AND LEMMATIZATION REPLACED WITH NLTK
   Old: hand-rolled tokenize() (regex + split) and lemmatize() (suffix rules).
   New: nltk.word_tokenize() for tokenization; WordNetLemmatizer + nltk.pos_tag()
        for lemmatization. Better accuracy on contractions, verb forms, plurals.

2. SPELL CORRECTION COMPLETELY REMOVED
   Old: working spell corrector (_spell_correct, edit_distance,
        _one_adjacent_transposition_away, SPELLCHECK_BLOCKLIST).
   New: all spell correction code removed. Reason: with NLTK lemmatization already
        handling morphological variation (beaches->beach, running->run), spell
        correction only introduced false positives — most dangerously,
        "like" -> "lake" -> nature (common word one edit from a vocab keyword).
        The SPELLCHECK_BLOCKLIST was a growing workaround that was never complete.

3. extract() SIGNATURE SIMPLIFIED
   Old: extract(text, keyword_map, allow_spellcheck=True, blocking_vocabulary=None)
   New: extract(text, keyword_map, blocking_vocabulary=None)
   allow_spellcheck parameter removed along with all spell correction logic.

4. POS TAGGING ADDED
   nltk.pos_tag() runs on the full token list once per extract() call. Each tag
   is converted to a WordNet POS constant so the lemmatizer picks the right
   inflection table (noun/verb/adjective/adverb).

5. negate_ttl CHANGED: 4 -> 20
   Old: negation carried forward 4 tokens.
   New: negation carries forward 20 tokens.
   Effect: "I definitely do not want to go somewhere warm" no longer drops
   the negation before reaching "warm" because of intervening filler words.

6. PUNCTUATION RESETS NEGATION (new)
   Old: negation window had no sentence-boundary awareness.
   New: sentence-ending punctuation (., !, ?, ;) resets pending_negate to False,
        so "I don't like beaches. I love mountains" correctly excludes beaches
        and includes mountains without the negation bleeding across sentences.

7. _match_exact_at() CHANGED
   Old: tried both space-joined AND no-space-joined candidates
        (e.g. "to"+"go" -> "togo", "south"+"america" -> "southamerica")
        max window: 3 tokens
   New: space-joined candidates ONLY (no-space join removed).
        max window: 5 tokens (increased to catch longer phrases).
   Reason: word_tokenize keeps "southamerica" as one token if typed that way,
   making the no-space join redundant. It was also causing false matches —
   "to"+"go" -> "togo" matched the country Togo, consuming negation from
   "do not want to go to Europe" and leaving Europe unexcluded.

8. NLTK DATA DOWNLOADS
   punkt, punkt_tab, averaged_perceptron_tagger, averaged_perceptron_tagger_eng,
   wordnet downloaded silently on first run.


================================================================
KNOWLEDGE_BASE.PY
================================================================

1. COUNTRY_REGION DICTIONARY ADDED
   Maps every dataset country to its region string.
   Used by country_to_region() helper.

2. COUNTRY_SYNONYMS VOCABULARY ADDED
   Maps typed variants to canonical country names (493 keys).
   Covers demonyms, capitals, abbreviations, common misspellings.
   NO overlap with CONTINENT_SYNONYMS — each token matches exactly one vocabulary,
   eliminating cross-slot false matches.

3. CONTINENT_SYNONYMS REDUCED TO PURE REGION WORDS
   Old: contained individual country names and city names (e.g. "japan"->"asia",
        "tokyo"->"asia", "paris"->"europe") — 297 overlapping keys with
        COUNTRY_SYNONYMS.
   New: only genuine region/continent words remain (70 keys: "europe", "asia",
        "scandinavia", "caribbean", "gulf", etc.). All country/city/demonym
        entries moved to COUNTRY_SYNONYMS.
   Effect: "japan" now only ever matches COUNTRY_SYNONYMS -> "Japan".
           No token can match both vocabularies simultaneously.

4. SEASON_SYNONYMS VOCABULARY ADDED
   Maps season/month words to canonical keys used by season_to_months().

5. SEASON_MONTHS AND MONTH_NUMBER DICTIONARIES ADDED
   SEASON_MONTHS: "winter"->[12,1,2], "spring"->[3,4,5], etc.
   MONTH_NUMBER:  "january"->1, "jan"->1, etc.

6. season_to_months() AND country_to_region() HELPERS ADDED
   season_to_months("summer") -> [6, 7, 8]
   country_to_region("Japan") -> "asia"

7. LIFESTYLE_DESCRIPTIONS ADDED (new, for TF-IDF)
   Nine keyword-rich strings, one per lifestyle dimension. Each includes the
   dimension name itself so direct mentions ("nightlife", "culture") get a
   TF-IDF match, alongside activity words for natural-language descriptions.
   Used by _match_lifestyle_dims() in chatbot.py.

8. DATA LOADING: csv MODULE -> pandas
   Old: csv.DictReader + manual for-loop.
   New: pd.read_csv(), .apply() for JSON columns, .to_dict(orient="records")
        to output the same list-of-dicts the inference engine expects.


================================================================
INFERENCE.PY
================================================================

1. cosine_similarity() REWRITTEN USING SCIPY
   Old: hand-coded dot product and norm using Python loops and math.sqrt().
   New: scipy.spatial.distance.cosine() (same library as chatbot__4_.ipynb).
        scipy_cosine() returns distance (1 - similarity), so result is 1 - that.
        numpy.linalg.norm() used for zero-vector guard.

2. VECTOR MATH USES NUMPY ARRAYS
   Old: user_vec and city_vec built as plain Python lists; sum()/len() for mean;
        max() generator for lifestyle_exclude.
   New: np.array() for vector construction; np.mean() for strength calculation;
        np.max() for exclude penalty. Same semantics, faster C-level execution.

3. SEASONAL TEMPERATURE SCORING ADDED
   When travel_months is set in the query, score_destination() uses the city's
   actual temperature for those months (via kb.seasonal_avg_temp()) rather than
   the yearly average. This means "warm in December" correctly favours Sydney
   over Stockholm.

4. explain_human() ADDED
   Human-readable per-city explanation facility for the GUI "Why this pick?" panel.
   Translates raw membership/CF values into plain-English bullets like
   "Climate — great match (warm, 26.1°C for your travel period)".
